# Reference Evidence

- Activate this rule when the task supplies visual references or a Reference UI Manifest is requested.
- Record visible reference facts separately from inferred responsive, interactive, long-content, and state behavior.
- Map every reference case to one target surface, required state, viewport, theme or locale when relevant, observable regions, interactions, dynamic regions, deviations, and acceptance policy.
- Treat an unambiguous reference as selected direction for the properties it visibly defines. Ask for a decision only where conflicting or missing evidence would change acceptance conditions.
- Preserve the existing design system and universal accessibility and safety requirements. Record necessary departures from the reference as explicit allowed deviations.
- Author the manifest only at `tasks/TASK-NNN/reference-ui/manifest.json`. Keep task identity stable; once validation evidence exists, any contract-content change requires a higher `manifestVersion`.
- Keep all output planning-only. Production UI, tests, baselines, staging, and validation evidence remain unchanged.
